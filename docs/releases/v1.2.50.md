# v1.2.50 — Full patch: dedup, per-abaya visual, kiosk badge, cross-day session fix

> **TL;DR:** This release bundles all fixes from v1.2.46–1.2.50 into one installable build.
> It is the first deploy since v1.2.45 to reach the factory PC via the electron
> launcher auto-update. Key fixes: the day-modal history strip finally agrees with
> PROCESS COMPLETED, per-abaya visual distinction lands on both the cloud dashboard
> and the offline dashboard, the cross-day dedup edge case is resolved, and the
> kiosk's "Working" badge clears immediately on Finish.

---

## Fixes included (v1.2.46 → v1.2.50)

### v1.2.46 — Day-modal history strip honors (emp_id, started_at) dedup

The Last 30 Days strip and the empty-day "nearby dates" chip on the per-employee
day modal now go through the same `dedupSessionsCte()` SQL layer as the rest of
the cloud read path. A worker-day that PROCESS COMPLETED correctly says is 3 now
also reads 3 on the Last 30 Days cell — no more "4u vs 3" mismatch.

### v1.2.47 — Per-abaya visual distinction on the cloud day-modal

The sessions list on the per-employee day modal now shows:
- A deterministic left-border tint per abaya (so two CF111 rows share the same
  border, a CF112 row has a different one)
- An 8px swatch dot before the abaya code
- A "Custom" pill on rows whose catalog entry has `is_custom=1`
- Five DOM data attributes (`data-session-id`, `data-abaya-id`,
  `data-abaya-code`, `data-started-at-ms`, `data-ended-at-ms`) for future
  audit hooks

### v1.2.48 — Per-day session dedup: cross-day clusters stay on their start day

The `dedupSessionsCte()` partition key now includes `day_date` alongside
`(emp_id, started_at)`. Before this fix, a session whose duplicate-pushed
Finish landed on the next calendar day could lose its count from the Start-day
aggregation. The mouthirrahman 09-20/09-21 cross-day case now reads consistently
across the board.

### v1.2.49 — Per-abaya visual distinction ported to the offline dashboard

The factory's offline dashboard at `192.168.0.101:3111/dashboard` now carries the
same per-abaya treatment (border, swatch dot, Custom pill, audit attrs) on the
Live Active Sessions, Recent Checker Logs, and Recent Invoice Logs panels.

### v1.2.50 — Kiosk: "Working" badge clears immediately on Finish

The demo grid's "Working" badge previously relied solely on the Socket.IO
broadcast to clear after a Finish tap. If the broadcast was delayed, the badge
stayed. The kiosk now clears the badge synchronously in the `ok: true` callback
from the server — before navigating to the confirmation screen.
