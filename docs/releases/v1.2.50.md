# v1.2.50 — Kiosk: "Working" badge now clears immediately on finish

## Bug fix

**The demo grid "Working" badge persisted after a worker tapped Finish.**

When a worker finished their session, the kiosk UI relied solely on the Socket.IO
`state_update` broadcast to clear the "Working" badge from the demo grid. If the
broadcast was delayed (Socket.IO reconnect, background tab throttling, or message
ordering), the badge remained stuck — making it look like the worker was still
working even after completing their session.

## What changed

### `public/kiosk.js`
- Added `window.__kioskSocket` as a test hook (line 35) — harmless in production.
- **Lines 1373–1381 (new):** After the server confirms `ok: true` in the
  `emitFinishWork` callback, the kiosk now immediately deletes the emp_id from
  `activeSessionsByEmployee`, rebuilds `lastActiveEmployeeIds`, and calls
  `renderDemoGrid()` — synchronously, before navigating to the confirmation
  screen. This removes the "Working" badge the moment the server says "done" —
  without waiting for the Socket.IO broadcast to arrive.

  ```js
  if (selEmp && selEmp.id) {
    delete activeSessionsByEmployee[selEmp.id];
    lastActiveEmployeeIds = Object.keys(activeSessionsByEmployee);
    renderDemoGrid(lastActiveEmployeeIds);
    updateFpActiveSessionsBanner();
  }
  ```

### `scripts/verify-kiosk-finish.mjs` (new)
- Playwright verification script for this exact flow.
- Finds an inactive employee, starts a session via Socket.IO, reloads the
  kiosk page to pick up the active session, triggers finish, and asserts the
  "Working" badge is gone immediately after the callback fires.
- Verified PASS on local server (16 active badges before → 15 after finish).

## Verification

node scripts/verify-kiosk-finish.mjs
