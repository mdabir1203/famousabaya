# v1.2.30 — Live Active Session Realtime Stream

## Summary

The Live Active Sessions panel on both the LAN factory dashboard and
the Cloudflare-hosted CEO dashboard now reflects Start/Finish events
within ~1 second end-to-end. Previously the cloud dashboard lagged
up to ~9.5s behind a real Start/Finish (5s server cache + 4.5s poll
cadence), and the LAN dashboard's elapsed-time counter rebuilt the
full row innerHTML every 2.5s — visibly stale when an operator is
staring at a busy board.

## What changed

### `cloudflare/src/handlers/state.js`
- New `?live=1` opt-in query param bypasses the 5s in-memory response
  cache (added in v1.2.26) on both the read and write sides. When the
  CEO dashboard sees at least one active session, it appends
  `&live=1` to `/api/state` and gets a fresh D1 read on every poll.
  When there are no active sessions, the dashboard falls back to the
  cached 4.5s view, so the free-tier D1 row_read budget stays
  healthy.
- JSDoc updated to document the new param and the trade-off.

### `cloudflare/src/ui/ceo-pages.js`
- `poll()` appends `&live=1` to the URL when `STATE.active` has
  entries. This is a per-poll decision: as soon as the last active
  session finishes, the next poll drops `live=1` and the 5s cache
  takes over again.
- `nextPollDelayMs()` returns **1000ms** when `STATE.active` is
  non-empty (was 2000ms), and 4500ms when idle (unchanged).
- Combined effect: ~1s end-to-end latency for live board updates
  when workers are tapping Start/Finish, while the idle baseline
  stays at 4.5s.

### `public/dashboard.js`
- Extracted two pure helpers from `renderLiveSessions`:
  `computeInShiftSec()` and `computeActiveTodaySec()`. These compute
  the elapsed-time values from `(startedAtSec, serverNowSec, …)`
  without touching the DOM, so the new 1Hz tick can call them
  without re-running the full render.
- New `tickLiveSessions()` function walks the active rows and
  updates ONLY the two elapsed-time cells via targeted
  `textContent` writes on `[data-tick="active-today"]` and
  `[data-tick="build"]` selectors. The cells now carry
  `data-emp-id="<id>"` so the tick matches them per worker.
- Replaced `setInterval(renderLiveSessions, 2500)` with
  `setInterval(tickLiveSessions, 1000)`. The full innerHTML rebuild
  still runs on every `state_update` socket event, so new/finished
  sessions appear immediately; the tick is purely a counter refresh.

## Resulting behavior

| Surface | Before | After |
|---|---|---|
| Cloud CEO dashboard — Start/Finish latency | up to 9.5s (5s cache + 4.5s poll) | **≤ 1s** (live=1 + 1s poll) |
| Cloud CEO dashboard — elapsed-time tick | 2-4.5s | **1s** |
| Cloud CEO dashboard — idle (no active) | 4.5s poll, cached | unchanged (4.5s poll, cached) |
| LAN factory dashboard — Start/Finish latency | ~16ms (socket) | unchanged (~16ms) |
| LAN factory dashboard — elapsed-time tick | 2.5s (full innerHTML rebuild) | **1s (textContent only)** |
| Kiosk | socket busy/idle markers | unchanged |

## Tests

Two new test files; 11 new cases; 132/132 unit + integration tests
pass.

- `tests/ceo-state-live.test.mjs` (5 cases): `?live=1` bypasses the
  cache on every call, non-live calls within TTL still hit the
  cache, the live call does NOT overwrite the cached non-live
  payload (the key behavior that keeps the idle D1 row budget
  healthy), live-mode responses don't carry `_cache.hit`, and
  `_invalidateStateCache` still works.
- `tests/dashboard-live-tick.test.mjs` (6 cases):
  `computeInShiftSec` correct over single-day / cross-day /
  out-of-window / edge cases, `computeActiveTodaySec` clamps
  cross-day sessions to today's midnight (TZ-aware), 60s
  granularity with partial last minute, dashboard.js schedules
  `setInterval(tickLiveSessions, 1000)` and NOT the old 2.5s
  loop, and the live row markup carries the `data-tick` /
  `data-emp-id` attributes the tick function needs.
