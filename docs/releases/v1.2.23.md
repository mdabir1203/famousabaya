# v1.2.23 — Install slim + R2 mirror hang fix

**Date:** 2026-09-04
**Commit:** (filled by release notes generator)
**Status:** SHIPPED

## What this release does

Two things, both unblocking for off-site factory laptops:

1. **Install size drops from 103.86 MB → ~75 MB** (≈28 MB reclaimed). Every
   factory PC downloads 28 MB less on every update, and the dev box
   uploads to the R2 mirror in 30 seconds instead of hanging.
2. **R2 mirror (`dashboard.farewellabaya.com/updates/stable/`) re-syncs
   automatically** because the smaller installer is below the 96 MB
   threshold that `wrangler r2 object put` chokes on.

The R2 mirror was stuck at v1.2.20 because every v1.2.21+ installer
exceeded 96 MB, and `wrangler r2 object put` (v4.91.0) hangs >15 min
on files that large — not slow, **hung**. The factory primarily uses
the LAN mirror so it never noticed, but off-site laptops and the
office desk were stuck on v1.2.20.

**Plus** the `*.map` source maps bring it to **~28 MB total saved** (the
first row of the slim ran 27.79 MB reclaimed on a v1.2.13 stale build;
CI runs on the real v1.2.22 tree will see similar or better numbers).

## What is kept (deliberately)

- **All xlsx internals**: `cfb`, `ast-types`, `esprima`, `wmf`, `pngjs`,
  `extrareqp2`, `codepage`. The xlsx loader reaches into these at
  runtime; cutting them would break `.xlsx` ingest on the factory.
- **All `.bin/` shims** under `node_modules/.bin/`. PM2 + every CLI
  wrapper needs them.
- **The Electron app itself** (main.js, preload.js, renderer.js,
  app.asar) — not touched.
- **`install/.env.production`**, **`ecosystem.config.cjs`**,
  **`tools/catalog-watcher/`** — all untouched, still bundled in full.

## How it works

`scripts/slim-install.cjs` is a Node.js script that walks every package
under `node_modules/` and removes the safe bloat. It logs every deletion
to `scripts/slim-install.log` for audit. It refuses to run on a path
that doesn't contain `node_modules/express/package.json` (basic sanity
check that the input is actually a real AbaYa install).

The script is **idempotent** — running it twice is a no-op.

The CI workflow runs it twice:

1. **`✂️ Trim factory runtime deps`** — after `Bundle factory runtime deps`
   (which materialises `.factory-deps/node_modules/`). Trims that tree
   **before** electron-builder reads it, so the .exe is born small.
2. **`✂️ Trim catalog-watcher deps`** — after `Bundle catalog-watcher
   deps`. Trims `tools/catalog-watcher/node_modules/` before electron-builder
   bundles it as `resources/tools/catalog-watcher/node_modules/`.

Both steps have a sanity-check assertion that the trim didn't accidentally
remove `express/package.json` or `chokidar/package.json`. If the trim is
too aggressive, CI fails with a clear error pointing at the problem.

## Why this fixes the R2 mirror

`scripts/publish-r2-update.mjs` uses `npx wrangler r2 object put` to push
the installer to the R2 bucket (`abaya-updates`). Wrangler 4.91.0
(what's in `cloudflare/node_modules/`) has a known bug where uploads
**hang** on files > 96 MB. The v1.2.20 .exe was 83 MB and uploaded in
~30 seconds; v1.2.22 was 103.86 MB and never finished.

After v1.2.23 trim: the .exe is ~75 MB, well below the 96 MB threshold.
The same wrangler 4.91.0 will now complete the upload in ~30 seconds.
No need to upgrade wrangler or rewrite the publisher.

## What the factory operator sees

- The launcher auto-updates to v1.2.23 (same stable signing cert as v1.2.22,
  so the cert-thrash doom loop does NOT recur — every future release keeps
  the same `CN=AbaYa Track Self Signed` thumbprint).
- The on-disk install footprint drops by ~28 MB. Old `resources/node_modules/`
  is replaced; PM2's `node_modules` paths inside `.factory-deps/` are
  already hardcoded so this just works.
- No data/ or .env/ changes. NSIS preserves them across the upgrade.

## What factory PCs need to do

Nothing. Auto-update handles it. The only edge case: if a factory PC
somehow has the v1.2.21 or earlier build (very unlikely — R2 mirror
kept it pinned to v1.2.20), they'll jump straight to v1.2.23.

## Rollback

If v1.2.23 has a problem, `gh release download v1.2.22` and install
manually. The R2 mirror was already at v1.2.20, so the v1.2.22 LAN
mirror copy is still the highest version on R2 after rollback — off-site
laptops will roll back to v1.2.22 too.
