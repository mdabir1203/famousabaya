# AbaYa Track Launcher v1.2.17

A coherence + forward-compat release for the local SQLite snapshot writer
(`shared/sqlite-snapshot.cjs`). The factory PC was shipping a snapshot
whose `sessions` table was empty even though `completed_count: 5898`,
and whose DDL silently diverged from the cloud D1 schema.

This release also adds `AGENTS.md` at the repo root — the single source
of truth for the data-shape and schema rules that keep the local
factory server, the local snapshot, and the cloud D1 in lock-step. Read
it before any future change to `shared/`, `cloudflare/src/`, `server.js`,
or the catalog / roster ingest paths.

## What changed

### Bug fix: local snapshot's `sessions` table was empty

- **Field-name drift:** the writer read `r.start` / `r.end`, but the live
  offline JSON produced by `server.js:1202-1205` uses `r.started_at` /
  `r.ended_at`. The `if (!Number.isFinite(startedSec) || …) continue`
  silently dropped every row, so the factory's offline dashboard
  disagreed with the cloud. Now reads `r.started_at ?? r.start` and
  `r.ended_at ?? r.end` — both shapes are supported for backward compat.
- **Unit drift:** the writer's `Math.floor(Number(r.start) / 1000)`
  assumed ms, but if the field name ever changed without the unit
  following, every row would have landed in year 2082. Added
  `normalizeToUnixSec()` helper that auto-detects ms vs sec by magnitude
  (> 1e12 → ms) so the writer is unit-agnostic.

### Bug fix: local snapshot diverged 21x from the cloud

- The writer had **no synthetic-emp_id filter**, but the cloud D1 has the
  `RAISE(IGNORE)` trigger from migration 0018 and the JS guard in
  `ingest.js:62`. The local snapshot was 5,622 / 5,898 synthetic rows
  (`e1..e26`, `test-smoke-emp`, `ALIGN_DEMO_*`, `TEST_*`,
  `POSTDEPLOY_PROBE`), so the per-employee / per-day counts on the
  local dashboard contradicted the cloud. Now the writer mirrors the
  cloud: `/^e_bc_\d+$/.test(empIdStr)` filter on both `sessions` and
  `active_sessions` loops.
- Meta is now honest: `completed_count` is the **actual inserted
  count**, not the input count. New keys `completed_logs_received` and
  `completed_logs_filtered_synthetic` preserve the input count and the
  rejection count for diagnostics.

### Forward-compat fixes (so future changes don't break the snapshot)

- **`canonicalProcess` mirrors the cloud's `canonicalEmpProcess`** —
  case-insensitive aliases, `khaka work → Hand Work`, etc. Previously
  the local writer handled only three exact-match aliases, so a log
  with `process: "khaka work"` would have ended up in
  `tailor_01_units` in the local snapshot and `hand_work_units` in the
  cloud. Now both paths normalize the same way.
- **`active_sessions` DDL has the cloud migration 0016 columns** —
  `effective_started_at`, `windowed_elapsed_sec`, `outside_shift`,
  `is_cross_day`. The local server doesn't push these yet, so the
  inserts default to `null` / `0`; the day the local server starts
  pushing them, the snapshot is already ready.
- **`abaya_catalog` DDL has `is_custom`** — cloud migration 0019's flag
  for multi-week CUSTOM builds. Preserved on round-trip so the live
  row's "Custom" pill in the CEO view matches the local dashboard.

### Tests

- `tests/sqlite-snapshot.test.mjs` rewritten as a 12-case executable
  spec for the rules above: new + legacy field names, synthetic
  filtering, second-unit verification, active_sessions filter, meta
  honesty, full `canonicalProcess` alias matrix, DDL column presence
  for `is_custom` and the migration 0016 live-state columns,
  forward-compat for new emp_id forms, and silent-bucketing of unknown
  process names.
- Full `npm test`: **57 / 57 pass** (was 45 before this release).

### Docs

- **`AGENTS.md`** at the repo root — the durable rules of the road
  (emp_id contract, timestamp contract, schema-mirroring rule,
  process-canonicalization contract, version + meta-honesty contract,
  release pipeline, and a 7-item change-pre-check checklist).

## What factory PCs will see

- The next time the snapshot is rebuilt (every ~5 minutes, or on
  `node scripts/snapshot-now.cjs`), the `sessions` table will
  populate with the real `e_bc_*` sessions instead of being empty.
  The local dashboard's per-employee and per-day counts will now match
  the cloud CEO view.
- The bundled v1.2.13 installer artifact at
  `tools/desktop-launcher/install-v1213-build/win-unpacked/resources/`
  still has the pre-fix writer. The next `electron-builder` run (the
  install flow itself) regenerates that from the fixed source.
  Factory PCs that update via the existing auto-update flow will get
  the fix automatically.
- No new dependencies. No `wrangler` / D1 schema change on the cloud
  side (all the new DDL columns and the `canonicalProcess` parity are
  client-side).
- No action required from the operator.

## Upgrade path

1. The desktop launcher's auto-update (electron-updater, stable ring)
   will pick up v1.2.17 once it's published to GitHub Releases and
   the LAN mirror.
2. Manual upgrade: install the new `AbaYa-Track-Launcher-Setup-1.2.17.exe`
   over the existing installation. The installer preserves the
   `data/` directory (roster, catalog, offline reports, snapshots).
3. Source-only upgrade (factory dev box): `git pull` and `node
   server.js` — the next snapshot rebuild will use the fixed writer.
