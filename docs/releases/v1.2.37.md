# v1.2.37 — Skip self-signed cert check + factory-server `.pnp.cjs` fallback

> **TL;DR:** Two fixes in one release:
>
> 1. **Skip cert verification** in the launcher so future builds ship
>    as `AbaYa Track Self Signed` install cleanly (the user explicitly
>    opted for self-signed distribution; a real code-signing cert is a
>    future operator action).
> 2. **Same `.pnp.cjs` fallback** that landed in v1.2.36 for the
>    catalog-watcher wrapper is now mirrored in the factory-server
>    wrapper. Both wrappers now detect whether `.pnp.cjs` exists and
>    fall back to plain `node server.js` / `node watch-catalog.js`
>    when missing — fixing the "PM2 not running" + "watcher .pnp.cjs
>    not found" failures on a freshly-installed factory laptop that
>    hasn't run `LAUNCH-ALL.bat` (which is what produces `.pnp.cjs`)
>    yet.

---

## 1. Self-signed cert verification disabled — `verifyUpdateCodeSignature: false`

### What changed

`tools/desktop-launcher/package.json#build.win`:

```diff
"win": {
  "target": [...],
- "artifactName": "AbaYa-Track-Launcher-Setup-${version}.${ext}"
+ "artifactName": "AbaYa-Track-Launcher-Setup-${version}.${ext}",
+ "verifyUpdateCodeSignature": false
}
```

This tells `electron-updater` 6.8.4's
`windowsExecutableCodeSignatureVerifier` to skip the publisher-name +
cert-chain check. Without this, every update attempt fails with:

```
LAST ERROR
New version 1.2.34 is not signed by the application owner:
publisherNames: AbaYa Track Self Signed, raw info: {
  SignerCertificate: { ... IssuerName: "CN=AbaYa Track Self Sign", ... }
}
```

because the `CSC_LINK_BASE64` GitHub Secret contains a self-signed
cert (Subject == Issuer, no chain to a trusted Windows root). The
factory laptop's currently-installed v1.2.33 is **also** self-signed
with the same name, so the "publisherNames match" check would
otherwise pass — but the verifier also blocks if the chain doesn't
reach a trusted root, which a self-signed cert always fails.

### Security trade-off (acknowledged)

With `verifyUpdateCodeSignature: false`:

- The launcher will install ANY signed EXE matching the version +
  sha512 in `latest.yml`, regardless of who signed it.
- An attacker who can MITM the LAN mirror at `192.168.0.x:3111/updates/
  stable/` or the cloud mirror at
  `https://dashboard.farewellabaya.com/updates/stable/` and substitute
  a malicious EXE with a matching version + sha512 hash can get it
  installed. (sha512 is checked separately; substitution requires
  forging both `latest.yml` and the .exe, which means also bypassing
  TLS + having the matching .pfx.)
- The factory LAN is air-gapped from the public Internet in normal
  operation, so the attack surface is reduced.
- The factory server + worker data lives at
  `%APPDATA%\AbaYa Track\factory-data\` and is never touched by the
  launcher install — only the launcher's own binaries in the install
  dir get replaced.

This is **acceptable for an isolated factory LAN** where the
operator controls the network. It is NOT acceptable if a factory
laptop ever traverses public Wi-Fi without a VPN. In that case
re-enable the check by removing the flag and ship a real code-signing
cert in `CSC_LINK_BASE64`.

### What this does NOT change

- `latest.yml` is still served by the same mirror.
- `electron-updater` still verifies the **sha512** of the downloaded
  EXE against the value in `latest.yml`. A wrong hash = rejected.
- `electron-updater` still does the **publisherNames match check**
  if both binaries happen to be signed by the same self-signed cert.
  The cert-chain-trust check is what's disabled.
- NSIS SmartScreen may still show "Unknown publisher" on first
  install of v1.2.37; that's a separate Windows-level check and
  cannot be skipped by electron-builder config. Operator can click
  "More info" → "Run anyway" once per laptop.

## 2. Factory-server `.pnp.cjs` fallback — mirror of v1.2.36 watcher fix

### What changed

`install/pm2-abaya-wrapper.js` now mirrors the same `.pnp.cjs`
presence check that landed in v1.2.36 for the catalog-watcher
wrapper:

```js
const PNP_PATH = path.join(ROOT, '.pnp.cjs');
const args = fs.existsSync(PNP_PATH)
  ? ['-r', './.pnp.cjs', 'server.js']
  : ['server.js'];
```

### Why this matters

The factory-server wrapper was originally fixed in v1.2.33 — but
the fix was **only for the catalog-watcher**. The factory-server
wrapper (`install/pm2-abaya-wrapper.js`) still hardcoded
`node -r ./.pnp.cjs server.js`. On a freshly-installed factory laptop
that hadn't yet run `LAUNCH-ALL.bat` (which is the script that
runs `setup.cjs` → `yarn install` → produces `.pnp.cjs`), the
factory-server wrapper would also crash with the same
`Cannot find module ... .pnp.cjs` cjs/loader error.

In practice this masked itself: the operator would see PM2
constantly restarting the `abaya-server` process. They would run
`LAUNCH-ALL.bat` to "fix" it (which produces `.pnp.cjs`), the
wrapper starts succeeding, PM2 stays online. Then the watcher
wrapper (also hardcoded `-r`) would fail the same way, the operator
would see the WATCHER LOG `.pnp.cjs` error — which is what we hit
in v1.2.33 / fixed in v1.2.36.

After v1.2.37:
- **Catalog-watcher wrapper** (fixed v1.2.36): falls back when
  `.pnp.cjs` missing.
- **Factory-server wrapper** (fixed v1.2.37): falls back when
  `.pnp.cjs` missing.
- A freshly-installed factory laptop boots cleanly with PM2 online
  for both processes, no `.pnp.cjs` errors, no `LAUNCH-ALL.bat`
  dance required before first use.

## What factory PCs will see after v1.2.37

The launcher will:

1. Probe the mirror for v1.2.37 → download in background.
2. Show "Install & Restart" in the trust row when ready.
3. On operator click (or auto-install-on-quit if enabled), NSIS
   replaces the binaries in `%LOCALAPPDATA%\Programs\AbaYa Track
   Launcher\`.
4. Restart into v1.2.37 — `migrateStaleFactoryEnv()` runs, no .env
   changes (no new HEAL_KEYS this release).
5. **`%APPDATA%\AbaYa Track\.env` untouched.** `data/`, `launcher/`
   untouched. PM2 + factory server + catalog-watcher all start.
6. **No more LAST ERROR** about "not signed by the application
   owner" — `verifyUpdateCodeSignature: false` lets electron-updater
   accept the self-signed v1.2.37 EXE.

The factory operator will see in the launcher's trust row:

```
v1.2.37 · Updated from v1.2.34 · [dismiss]
```

After install, no "STUCK" sessions, no LAST ERROR, no PM2 warnings,
no watcher crashes.

## Why two PnP-related fixes instead of one (v1.2.36 + v1.2.37)

The v1.2.36 commit only fixed the **catalog-watcher** wrapper.
The factory-server wrapper was originally fixed in v1.2.33 — but
that fix had a different shape (it relied on `interpreter: 'node'`
in `ecosystem.config.cjs` so PM2 didn't pass `-r ./.pnp.cjs` to the
wrapper). When the v1.2.33 watcher's wrapper was added with the
hardcoded `-r`, the original factory-server wrapper's fix was
forgotten in the new design. v1.2.36 fixed the watcher; v1.2.37
fixes the factory server for the same edge case.
