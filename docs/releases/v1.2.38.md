# v1.2.38 — Fail-fast CI when Cloudflare R2 secrets are missing

> **TL;DR:** All three CI builds since v1.2.35 (v1.2.35, v1.2.36, v1.2.37)
> failed the "Publish to R2 OTA feed" step — but only because the
> `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` GitHub Secrets
> **were never set** (verified via `gh secret list`). `wrangler`
> silently failed auth, the verify step saw the old R2 latest.yml,
> and the CI reported "failure" on the R2 step but the GitHub
> Release still shipped. From the operator's perspective, the
> launcher kept polling stale mirrors.
>
> v1.2.38 adds an explicit guard so the CI fails fast with a clear
> "configure these secrets" message instead of a cryptic wrangler
> auth error. Until the operator adds the secrets, every build
> will keep failing the R2 step and the manual workaround (run
> `node scripts/publish-r2-update.mjs` from a dev box with the
> secrets in `.env`) remains the production path.
>
> **No binary changes** — the same v1.2.37 binaries ship with this
> version bump.

---

## What happened

The v1.2.35 OTA-pipeline fix (commit `a3b0466`) added three CI
steps to the release workflow:

1. `☁️ Publish to R2 OTA feed` — runs `node scripts/publish-r2-update.mjs`
   with `CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}`
   and `CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}`
2. `✅ Verify R2 mirror reachable` — probes the dashboard, fails CI
   if the version doesn't match
3. `📝 Print LAN mirror publish instructions`

All three v1.2.35, v1.2.36, v1.2.37 CI builds reported **failure**
on step 1 with the same cryptic wrangler auth error:

```
⛅️ wrangler 4.91.0
[ERROR] A request to the Cloudflare API (...)
  Authentication error [code: 10000]
```

Verified via `gh secret list`:
```
GH_TOKEN                  2026-08-30T16:32:21Z
CSC_KEY_PASSWORD          2026-09-02T20:52:48Z
CSC_LINK_BASE64           2026-09-03T19:13:54Z
WIN_CSC_LINK_BASE64       2026-09-03T19:13:56Z
```

**`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are missing.**
The workflow was wired up to read them but they were never set.

## The fallback that worked

Because `publish-r2-update.mjs` reads `process.env.CLOUDFLARE_API_TOKEN`
locally too, the operator (me, on the dev box) ran:

```bash
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... \
  node scripts/publish-r2-update.mjs --channel stable
```

on this dev box, which is authenticated via the local wrangler
OAuth (`~/.config/.wrangler/config/default.toml`). The R2 mirror
got v1.2.34, v1.2.36, and v1.2.37 manually as a result.

The CI failures were **silent** because the verify step ALSO
skipped (the script `exit 1`'d on auth, the next step ran with
`if: always()`-equivalent — wait, actually the verify step runs
regardless of the publish step's status, and the verify step
correctly **skipped** because the next step's `if:` condition was
`failure()` of the publish step, not `always()`. Let me verify...).

Actually looking at the YAML structure I added: the verify step has
no `if:` clause, so it runs by default — **but** because the R2
publish step **failed** (not succeeded), the entire job marked as
"failure". The verify step ran and saw the stale `latest.yml` (still
v1.2.23 from Sep 4), so it ALSO failed — making the CI double-fail.

## The fix in v1.2.38

The R2 publish step now checks for the secrets FIRST and fails
fast with a clear error message:

```yaml
- name: ☁️ Publish to R2 OTA feed
  shell: bash
  env:
    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
    CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
  run: |
    if [ -z "$CLOUDFLARE_API_TOKEN" ] || [ -z "$CLOUDFLARE_ACCOUNT_ID" ]; then
      echo "::error::CLOUDFLARE_API_TOKEN and/or CLOUDFLARE_ACCOUNT_ID secrets are missing."
      echo "::error::Add them at https://github.com/mdabir1203/famousabaya/settings/secrets/actions"
      ...
      exit 1
    fi
    node scripts/publish-r2-update.mjs --channel stable
```

Now the CI log will show **exactly** what the operator needs to
fix, instead of `Authentication error [code: 10000]`.

## Operator action required

Either:

### Option A — Set the secrets in GitHub (recommended)

1. Get a Cloudflare API token with **R2: Object Storage Edit**
   permission: https://dash.cloudflare.com/profile/api-tokens
2. Get the Account ID: https://dash.cloudflare.com → Workers & Pages
   → right sidebar "Account ID"
3. Add to GitHub repo secrets:
   ```bash
   echo -n "your-api-token" | gh secret set CLOUDFLARE_API_TOKEN -R mdabir1203/famousabaya
   echo -n "your-account-id"  | gh secret set CLOUDFLARE_ACCOUNT_ID -R mdabir1203/famousabaya
   ```
4. Push a trivial commit to trigger rebuild. The R2 step will now
   succeed.

### Option B — Continue using the manual fallback

Until Option A is done, the operator must run `publish-r2-update.mjs`
from a dev box with the secrets in the local environment. This is
the path that produced v1.2.34 / v1.2.36 / v1.2.37 / v1.2.37 on
R2 today. The CI workflow's new fail-fast just makes the missing
secrets obvious so Option A becomes the obvious next step.
