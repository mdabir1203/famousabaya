# v1.2.22 — Properly bundle the catalog-watcher (not remove it)

**Release date:** 2026-09-04
**Type:** patch (revert tactical v1.2.21 fix; ship the strategic one)
**Builds on:** v1.2.21

---

## What this release fixes

v1.2.21 was a tactical fix — I removed the `tools/catalog-watcher`
extraResources entry to stop the install-time crash. That was the
wrong call. The catalog-watcher is a real, useful tool (LAN photo
sync + cloud-watcher demo for the office), and removing it from
the install is a product regression.

This release brings the watcher back, properly bundled.

## The proper fix (replaces v1.2.21's removal)

**Switch the watcher from Yarn PnP to node-modules linker:**

`tools/catalog-watcher/.yarnrc.yml`:
```yaml
nodeLinker: node-modules
enableGlobalCache: false
```

**Materialize the watcher's deps in CI:**

New step in `.github/workflows/release-desktop-launcher.yml`,
runs after the factory-deps step:
```pwsh
Push-Location tools/catalog-watcher
npm install --omit=dev --no-audit --no-fund --loglevel=error
Pop-Location
```

**Bundle the watcher's node_modules via extraResources:**

`tools/desktop-launcher/package.json`:
```json
{
  "from": "../../tools/catalog-watcher",
  "to": "tools/catalog-watcher",
  "filter": [
    "*.js", "*.json", "*.cjs", "*.mjs", "*.txt",
    "package.json", "yarn.lock",
    "node_modules/**/*"
  ]
}
```

**ecosystem.config.cjs already handles the no-PnP case:**
the `interpreter_args` line `fs.existsSync(watcherPnp) ? ['-r',
'./.pnp.cjs'] : []` becomes `[]` (no PnP file in the install), so PM2
spawns `node watch-catalog.js` directly, which finds the deps in the
local `node_modules/`. The PnP fallback is now a safe no-op.

## Why the original was broken

The catalog-watcher uses Yarn PnP. The `.pnp.cjs` (PnP manifest) and
`.yarn/cache/` (offline package mirror) are gitignored — they only
exist on the dev box. Every CI build since v1.2.13 has shipped
the install with `tools/catalog-watcher/` containing `config.json`
+ `watch-catalog.js` but no PnP runtime, so the first `require()`
threw. v1.2.13–v1.2.19 installers never saw it because they hit
"PM2 NOT INSTALLED" first; v1.2.20 fixed PM2 and the watcher became
the new top error.

Switching the watcher to `node-modules` linker means `npm install`
produces a real `node_modules/` tree (like the factory server's
`.factory-deps/` does). That gets bundled cleanly into the install.

## Apply when

- v1.2.21's "remove the watcher" caused office-side operators
  to lose the LAN photo sync + cloud-watcher. v1.2.22 brings
  it back, properly bundled.
- Future operators who add a new yarn-PnP-using tool to
  `extraResources`: either (a) commit `.pnp.cjs` and
  `.yarn/cache/` to git, (b) add a node-modules `.yarnrc.yml`
  + a "Bundle X deps" CI step like the one for
  `tools/catalog-watcher/`, or (c) don't bundle the tool.
  PnP runtime MUST be on the CI runner, otherwise the install
  will crash on first boot.
- A factory install logs "WATCHER LOG → throw firstError" —
  the operator is on v1.2.20 or earlier. Auto-update will
  pick up v1.2.22 once it's released.
