# AbaYa Track Launcher v1.2.7

A focused stability and clarity release. The Check Report feature is gone, the
Daily/Weekly/Monthly/Yearly reports now tell you exactly who did what and when,
the dashboard renders 5× faster on busy days, and the installer + auto-update
pipeline finally ships one version that everything agrees on.

---

## What's in this release

### 🧹 Removed: Check Report
- Removed the Check Report button from the dashboard, the modal, and the
  backing backend (`server.js`, the Cloudflare `check-report` handler, and 4
  related routes).
- Removed `CF_INGEST_SECRET`/FACTORY_TZ/DEFAULT_FACTORY from the legacy
  configuration; moved `shared/check-report.cjs` and the related Cloudflare
  migration under `_backup_check_report_removed/`.
- Result: ~516 lines of dead JS gone from `public/dashboard.js`, smaller
  bundle, one less workflow to test.

### 📊 Absolute clarity in the Daily / Weekly / Monthly / Yearly reports
- **Day-by-day breakdown** in every report — for each day: weekday, date,
  units produced, time spent, and share % of the period total. No more
  "is it Tuesday or Wednesday?" guesswork.
- **What work was done by process** — every report now lists each process
  (cut, stitch, finish, …) with its unit total, so you can see at a glance
  where the day's work went.
- **Per-employee share %** column on the summary table — no more mental
  math to figure out who carried the day.

### ⚡ Faster dashboard
- All realtime renderers (KPIs, Employee perf, Pareto, Process eff, Hourly
  chart, Abaya totals) now go through a **single-pass `aggregateRealtime`**
  function instead of 4–5 separate `forEach` passes over the same log list.
- LRU cache keyed on log fingerprint; cache hits render in **0 ms**.
- Bench: 50k logs cold = **35.6 ms** (was 151.7 ms); 50k full pipeline cold
  = **114 ms** (was 485 ms). On a typical 1k–5k log day the dashboard
  re-renders are now effectively instant.
- Per-log table capped at 200 rows with a "Showing newest 200 of N" footer
  to keep the DOM small on heavy days.

### ☁️ Cloudflare D1 hydration
- New endpoint `GET /api/state/history?days=N` (1–365, max 50k rows) on the
  Cloudflare Worker. Authenticated by `X-Ingest-Secret` so the LAN factory
  server can pull without a CEO session.
- The factory server now hydrates up to **90 days of history** from D1 on a
  fresh install / empty snapshot. Result is exposed at
  `state.state_meta.d1_hydration` (completed / hydrated / count / days /
  truncated / fromYmd / toYmd / reason / error / ms) so you can see what
  happened at a glance.
- Set `CF_INGEST_SECRET=…` in `.env` to enable. (Default is empty → 401,
  hydration completes with `reason: "error"` and the rest of the system
  continues to work on the local snapshot.)

### 🛠️ Auto-detect + merge legacy data
- New `scripts/migrate-legacy-installs.cjs` walks `~/Downloads`,
  `~/Desktop`, `~/Documents`, and `~/AppData/Local/Programs` looking for
  older AbaYa installs, fingerprint-matches them (version + size + mtime)
  to skip the current one, and merges newer work-types / employee rosters
  / catalog data into `data/` without ever overwriting or deleting source.
- Run once with `node scripts/migrate-legacy-installs.cjs` (add `--scan`
  for a dry run, `--yes` to apply).

### 🚀 Single canonical version everywhere
- The release tag is now always **`v1.2.7`** — read directly from
  `tools/desktop-launcher/package.json`. The previous date-stamped
  variants (`v2026.08.09-141554` etc.) are gone.
- The release workflow uses `--publish never` for the electron-builder step
  and a single `gh release create` for the GitHub release — no more
  duplicate releases.
- The `latest.yml` shipped in the release is byte-identical to the one
  served by the LAN mirror at `/updates/stable/`, which is byte-identical
  to the EXE attached to the release. One source of truth, three places.
- Removed ~437,000 lines of deadweight from the git history (raw
  `install-v127/` electron build, intermediate `build-out-1.2.7/` and
  `build-prepacked-1.2.7/`); added patterns to `.gitignore` so future
  builds never re-commit them.

### 🔧 Misc fixes
- Launcher `index.html` grid layout fixed (`1fr 1fr` →
  `repeat(auto-fit, minmax(360px, 1fr))`); `pre` blocks get
  `overflow-wrap: anywhere` so long URLs/log lines no longer break the
  layout.
- Default window 980×640 → 1180×760.
- `START-Launcher-GUI.bat` switched from `corepack yarn` to plain `yarn`;
  `scripts/run-launcher.cjs` now strips `NODE_OPTIONS` from the child
  environment so the PnP loader doesn't leak into the spawned launcher.
- Killed two stale orphaned installs in `~/Downloads` that were holding
  port 3111 with an old Bun server. The factory server now starts clean.

## How to install / update

### Fresh install
Download `AbaYa-Track-Launcher-Setup-1.2.7.exe` (95.8 MB) below and run it.
The installer is a self-contained NSIS bundle that drops the launcher, the
factory server, the Cloudflare Worker config, the catalog watcher, and the
Electron app into one folder. No separate runtime, no Node.js install.

### Update from a previous version
The launcher checks the LAN mirror at startup. If your factory server is
running v1.2.7 it will pick up the same version (no prompt) and the
`latest.yml` is in sync with the EXE attached to this release.

For a clean install over a previous version, just run the new EXE — the
NSIS installer handles the upgrade in place and keeps your `data/`
folder intact under `%APPDATA%\AbaYa Track`.

---

## What to check after upgrading

1. **Launcher window** opens with title "AbaYa Track - Control Center".
   Auto-updater should report "Update for version 1.2.7 is not
   available" (i.e. you're already on the latest).
2. **Dashboard** at `http://<factory-pc>:3111/dashboard.html` renders
   the live tiles without flicker; switching to any report tab
   (Daily / Weekly / Monthly / Yearly) shows the day-by-day breakdown
   and per-process totals.
3. **Cloud sync** — if you've set `CF_INGEST_SECRET` in `.env`, the
   factory server should hydrate up to 90 days of history on first
   boot. Watch `state_meta.d1_hydration.completed` in
   `GET /api/state` go from `false` to `true` and `count` rise to
   your actual log count.
4. **LAN auto-update** — from a tablet or another PC on the same
   network, hit `http://<factory-pc>:3111/updates/stable/latest.yml`
   and you should see `version: 1.2.7` with the matching SHA512.

## Compatibility

- **OS:** Windows 10 / 11 x64. Server runtime is bundled; no Node.js
  required on the install PC.
- **Existing data:** upgrade keeps `%APPDATA%\AbaYa Track` intact. The
  legacy migration script in `scripts/migrate-legacy-installs.cjs`
  can pick up older installs from `~/Downloads`, `~/Desktop`,
  `~/Documents`, and `~/AppData/Local/Programs` and merge them in.
- **Auto-update channel:** LAN mirror by default
  (`http://<factory-pc>:3111/updates/stable/`), falls back to GitHub
  Releases if the mirror is unreachable. Override via
  `ABAYA_UPDATE_MIRROR_BASE_URL` in `.env`.
