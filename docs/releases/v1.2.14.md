# AbaYa Track Launcher v1.2.14

A small consistency fix on the local factory dashboard's Daily / Weekly / Monthly
/ Yearly / Custom report "Per-employee summary" panel.

The local factory server accumulates sessions in an in-memory `STATE.logs`
across the day, including smoke-test runs and synthetic employee IDs the QA
pipeline uses. The cloud dashboard is built server-side from the D1
`sessions` table, which only contains sessions the factory server
explicitly pushed via the cloud ingest secret — smoke-test sessions never
got pushed, so the cloud dashboard never had them.

The local dashboard's `summarizeLogsByEmployee` (and `employeeFilterOptions`)
client-side aggregator grouped all logs by `emp_id` and fell back to
showing the raw ID as the employee name when the id wasn't in the real
employees roster, which is what leaked `e13`, `e7`, `test-smoke-emp` etc.
into the per-employee summary.

This release adds a single guard in both functions: if `emp_id` is not in
the real employees roster (`empById`), the log is skipped. The cloud
Worker needs no change — it already only ever sees pushed sessions.

## Headline changes

- `public/dashboard.js` `summarizeLogsByEmployee` skips logs whose
  `emp_id` is not in `empById` (the real employees roster). This
  matches the cloud Worker's behaviour of only ever seeing pushed
  sessions.
- `public/dashboard.js` `employeeFilterOptions` (the "All employees"
  dropdown) applies the same filter, so the test IDs no longer appear
  in the filter options.
- No backend / Worker / D1 changes. The cloud `report.js` handler
  is unchanged.
- `tools/desktop-launcher/package.json` bumped to 1.2.14.

## What factory PCs will see

- The Daily / Weekly / Monthly / Yearly / Custom report "Per-employee
  summary" panel now shows only employees present in the real roster
  (`data/employees-manual.json` on the factory server, hydrated into
  the dashboard's `empById` map). Smoke-test and synthetic IDs disappear
  from both the per-employee list and the "All employees" filter.
- The cloud dashboard at `dashboard.farewellabaya.com` is unchanged
  (it already filtered implicitly via the pushed-data path).

## Operational notes

- No D1 migration.
- If a real employee's `emp_id` in `data/employees-manual.json` is
  missing or mistyped, that employee's rows will disappear from the
  per-employee summary. Check the roster after upgrading.
- The fix is a one-line guard, scoped to client-side aggregation only.
  The factory server's `STATE.logs` still contains the test sessions
  for debugging — only their display is suppressed.
