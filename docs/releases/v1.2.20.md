# v1.2.20 — All-in-one install audit: PM2, env, cloudflared

**Release date:** 2026-09-02
**Type:** patch (coherence / install-bundle audit fixes)
**Builds on:** v1.2.19

---

## What this release fixes

A v1.2.19 fresh install on the dev box exposed that the
all-in-one installer (`yarn dist:win` output) was **not bundling
three files the runtime expected to find under `resources/`**.
The launcher silently fell back to "inline spawn" for the server,
the env-migrate self-heal had no source of truth, and the
cloudflared-tunnel PM2 app had no config. The factory never
noticed because (a) PM2 wasn't being used anyway, and (b) the
factory's `INSTALL.bat` seeds `.env` from outside the packaged
install.

This release makes the packaged install self-sufficient so a
fresh `AbaYa-Track-Launcher-Setup-1.2.20.exe` on a virgin laptop
ends up with a working PM2-managed factory server, a real
`.env` with the cloud credentials + LAN mirror URL, and the
cloudflared config ready to be edited for the local tunnel.

## Audit findings

| # | File | Repo? | v1.2.19 install? | Impact |
|---|---|---|---|---|
| 1 | `ecosystem.config.cjs` | ✅ | ❌ | PM2 always failed → fell back to inline spawn. Dashboard log: `[launcher] PM2 start failed; falling back to inline spawn.` |
| 2 | `install/.env.production` | ✅ (3,191 B) | ❌ | env-migrate self-heal had no source of truth. Fresh installs started with `.env.example` (no `CF_INGEST_SECRET`, no `ABAYA_UPDATE_MIRROR_BASE_URL`, no `LAN_IP`) → 401 on every cloud push until operator hand-edits |
| 3 | `config/cloudflared.config.yml` | ✅ | ❌ | `config/` filter was `**/*.json` only — `.yml` files never bundled. cloudflared-tunnel PM2 app would fail to find its config |

## Files changed

- `tools/desktop-launcher/package.json`
  - **Added** `ecosystem.config.cjs` to `extraResources`
  - **Added** `install/.env.production` to `extraResources` (also
    dropped the broken `"filter": [".env.production"]` — file
    sources don't apply the filter, and the literal-dot pattern
    wasn't matching anyway)
  - **Broadened** the `config/` filter from `**/*.json` to
    `**/*.{json,yml,yaml}` so cloudflared config ships
- `package.json` — version bump 1.2.19 → 1.2.20
- `tools/desktop-launcher/package.json` — version bump 1.2.19 → 1.2.20

## What the factory operator will see

After installing v1.2.20 on the factory (or running it for the
first time on the dev box), clicking **Start Runtime** in the
launcher now produces:

```
[launcher] pm2 start ecosystem.config.cjs → ok
[launcher] pm2 save → ok
PM2: abaya-server (online)        ← instead of NOT INSTALLED / inline spawn
SERVER: <pid>
WATCHER: <pid or -
TUNNEL: -                          (until cloudflared config is set)
```

Reboot persistence now works because `pm2 save` registers the
process dump; `pm2 startup` (run once on the factory) hooks the
PM2 daemon into OS boot. The cloud credential auto-heal from
v1.2.18 also now functions on fresh installs — the bundled
`.env.production` gives `env-migrate` something to compare
against.

## Test coverage

`npm test` → 57/57 pass, 0 fail (no source changes that affect
covered paths; only build-config changes).

## Apply when

- The factory installs a fresh v1.2.20: PM2 manages the server
  (reboots work), env-migrate keeps `.env` aligned, cloudflared
  config is on disk
- The dev box upgrades to v1.2.20: same wins, plus the orphaned
  `ecosystem.config.cjs` copy workaround is no longer needed
- A future installer audit asks "did we ship this file?":
  `extraResources` in `tools/desktop-launcher/package.json` is
  the canonical inventory
