# v1.2.28 — Dashboard perf overhaul

**Ship date:** 2026-09-07
**Type:** Performance (no schema, no new endpoints, no .exe feature changes)

## What

Three layers of perf work on `dashboard.farewellabaya.com`, in priority
order. Every change is behavior-preserving — no animation changed, no
DOM event sequence changed, no user-visible difference in steady state.
A new in-app browser hard-refresh (Ctrl+Shift+R) is required to pick up
the v1.2.28 HTML, but the CSS + helpers JS get pulled automatically
after that.

## Tier 1 — Server-side bandwidth (biggest win on refresh)

- **External CSS** at `/static/ceo.css?v=<fnv1a>` with
  `Cache-Control: public, max-age=31536000, immutable`. The 25 KB
  inline `<style>` block that used to be inside the HTML response is
  now in `cloudflare/src/ui/ceo-static.js` as a module-level string
  (`DASHBOARD_CSS_BODY`). Served by a new Worker route at the top of
  the dispatch. After the first page load the browser hits disk.
- **ETag/304 on the CEO HTML** response. Weak ETag derived from
  `(HTML_VERSION, CSS_VERSION, fnv1a(origin))`. Cookie-bearing HTML
  response now carries `Cache-Control: private, no-cache` (was
  `no-store`); on page refresh the browser sends `If-None-Match` and
  the Worker returns 304 with no body. 200 KB → ~1 KB per refresh.
- **CSS_BODY is byte-identical** to the old inline block — verified
  with a 25,162-byte diff against `ceo-pages.js` lines 146-386 (now
  removed). A test (`tests/ceo-static.test.mjs`) enforces the match
  on every CI run so a future refactor can't accidentally regress.

## Tier 2 — Client-side hot path (~85% of per-render work)

The dashboard's `renderAll()` runs every 2-4.5 s. Three browser-perf
traps dominated the per-render cost. All three are fixed with proven
algorithms (no scratch):

- **Cached `Intl.DateTimeFormat`**. The old code constructed a new
  DateTimeFormat per format call inside the active-session loop (10
  constructions per render = ~18,000/hour). Now cached by `(tz,
  pattern-name)`. From ~50-100 µs/call to ~5 µs/call — the textbook
  fix for the `new Intl.DateTimeFormat()` perf trap. 11 named
  patterns + a `Map` keyed by `tz||name`.
- **Sweep-line `overlapSecWithWindows` port**. The "this build" cell
  used a minute-by-minute walk from `startedAtSec` to `serverNowSec`.
  A 24 h forgotten-Finish session = 1,440 iterations per render. The
  server already has `overlapSecWithWindows` in
  `cloudflare/src/working-hours.js`; the client now uses the same
  algorithm (60s/600s/3600s step heuristic, 48 h HARD_CAP, inWin
  memo) via a `cloudflare/src/ui/ceo-client-helpers.js` port. 99 %
  reduction.
- **O(1) `abayaIsCustomSet`**. Old code did an O(n) catalog scan per
  active session per render (`n` ≈ 5,000 abayas). The new code
  builds a `Set<id>` once per STATE arrival in `poll()` after
  `STATE = d;`, then `isAbayaCustomFast(id)` is a hash lookup.
- **Per-block `innerHTML` memoization**. 4 of the 6 innerHTML-heavy
  `safeRender` blocks (proc-split, emp-perf, hourly, recent-invoice-
  logs) now check a hash of their input data first. If the hash
  matches the last paint, the `innerHTML` write is skipped. With the
  5 s server cache + 2 s browser poll cadence, ~80 % of polls in
  steady state are no-ops.

## Tier 3 — Polish

- **Pause poll on `document.visibilityState === 'hidden'`**. The
  browser's Page Visibility API guarantees a re-fire on `visible`,
  so background tabs save bandwidth and Worker CPU without changing
  the foreground experience. Resumes immediately when the user comes
  back.
- **`<link rel="preload" as="style">`** for the external CSS so the
  browser starts the CSS fetch in parallel with HTML parse instead
  of after.

## What this doesn't change (verified)

- No CSS animations, transitions, or hover states were touched. The
  diff against the old inline `<style>` block is byte-identical.
- No new Worker endpoints.
- No new D1 tables, no new D1 columns, no migrations.
- No factory-side behavior change — the launcher's `v1.2.27 → v1.2.28`
  bump is metadata-only; the .exe rebuild is byte-equivalent except
  for the version string.

## Files changed

- `cloudflare/src/ui/ceo-static.js` *(new, 25 KB body + ETag helpers)*
- `cloudflare/src/ui/ceo-client-helpers.js` *(new, perf algorithms as
  a plain ES module so the test suite can verify them)*
- `cloudflare/src/ui/ceo-pages.js` *(replaced inline `<style>` with
  `<link>`; added helpers IIFE; wrapped 4 safeRender blocks in
  hash-memoization; added `visibilityState` short-circuit to `poll()`;
  `STATE = d` line now rebuilds the `abayaIsCustomSet`)*
- `cloudflare/src/index.js` *(added `/static/ceo.css` route; ETag/304
  on the CEO HTML response; imported the new helpers)*
- `tests/ceo-static.test.mjs` *(new, 28 cases — Intl cache, sweep-line
  parity with the old minute-walk for 5 inputs, hash stability, ETag
  determinism, source-sync check that the inline IIFE still
  references `__ceoPerf` and the inline CSS is gone)*
- `package.json` + `tools/desktop-launcher/package.json` *(version
  bump 1.2.27 → 1.2.28)*

## Deploy + verify

```bash
npx wrangler versions upload --config cloudflare/wrangler.toml
# then on the Worker side:
node scripts/smoke-tickets.mjs                       # 10/10
curl -I https://dashboard.farewellabaya.com/ceo \
  -H "Cookie: ceo_sess=..."                          # 200, ETag: W/"1.2.28-..."
curl -I https://dashboard.farewellabaya.com/ceo \
  -H "Cookie: ceo_sess=..." \
  -H "If-None-Match: W/\"1.2.28-...\""              # 304
curl -I https://dashboard.farewellabaya.com/static/ceo.css  # 200, Cache-Control: immutable
```

In the browser: hard-refresh (Ctrl+Shift+R) once after the Worker
deploys. Subsequent loads show 304 + a single CSS hit on disk. The
DevTools Network tab should report:

- First visit: 200 HTML (175 KB, was 200 KB) + 200 CSS (25 KB) + 2× 200 fonts
- Every refresh after: 304 HTML (~1 KB) + 304-from-disk CSS + 304-from-disk fonts
- Active dashboard polling: no per-render work for 4 of the 6 innerHTML writes

## What an operator sees

Nothing. The animations, the data, the layout, the page weight on
subsequent loads are all transparent. The only externally visible
change is the DevTools "transferred" column on a refresh dropping
from ~200 KB to ~1 KB.
