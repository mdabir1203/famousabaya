**Release date:** 2026-09-02
**Commit range:** 51dccc6…505f5fd (3 commits on `main`)
**Type:** minor feature + operator tool

## What changes for the operator (dashboard)

The Live Active Sessions card on the CEO Dashboard gains a **new top-right cell**:

```
                                    02:14:32          ← NEW, hero, ticks every 2.5s
                                    active today · Button
                                    10:35:42
                                    last finished · 01 Sept
                                    04:23:12
                                    this build · started 30 Aug
```

- **active today · `<ProcessName>`** — in-shift elapsed time for the current
  active session, ticking live. Resets at factory-TZ midnight for
  cross-day sessions. Mirrors the cloud D1's `windowed_elapsed_sec` column
  (added in cloudflare/migrations/0016); the local server doesn't push that
  column yet, so the dashboard recomputes it from `started_at` against the
  configured shift windows.
- The existing "last finished" and "this build" cells move down a slot
  (no change to their content or behavior).

**Why:** the right column previously had no live timer, so the operator
could only infer activity by squinting at two static timestamps. With the
new cell, "who's been on Button for the last 18 minutes" is at a glance.

## What changes for the operator (factory laptop)

A new `scripts/reset-orphan-sessions.ps1` ships with the install. Use it
when the in-memory active-sessions map has rows the operator forgot to
tap Finish for (power-cut, lunch break, end-of-day). The script:

1. Queries `/api/state` + `/api/employees` on the local factory server
2. Filters to sessions older than `-MinAgeMinutes` (default 120) AND
   currently outside the shift window
3. Shows the candidate list, asks `YES` to confirm
4. POSTs to the new `/api/admin/close-stale-sessions` endpoint on the
   local server with `auto_closed: true` so the cloud D1 can
   distinguish an operator cleanup from a real worker Finish
5. The local server then: removes from `ACTIVE_SESSIONS`, appends a
   completed log row with `end = min(started + 8h, now)` (a realistic
   upper bound on the work that actually happened), pushes
   `session_finish` to the cloud, re-saves both the offline-report
   snapshot and the SQLite snapshot

**Auth:** `X-Ingest-Secret` (same header as `/api/reconcile-now` and
`/api/cloud-today/refresh`). The script reads `CF_INGEST_SECRET` from
`$env`, then from `.env` next to the script, then prompts.

**Quick run (dry-run first):**
```powershell
pwsh -File scripts\reset-orphan-sessions.ps1 -DryRun
pwsh -File scripts\reset-orphan-sessions.ps1
```

**Just Wahid:**
```powershell
pwsh -File scripts\reset-orphan-sessions.ps1 -EmpId e_bc_00000138 -AssumeYes
```

## What changes for the operator (auto-update)

The auto-update mechanism was failing on the v1.2.13 → v1.2.17 transition
because the self-signed cert on the factory ("AbaYa Track Self Signed")
didn't match the cert on the GitHub release. This release documents the
manual-install workaround:

1. Download `AbaYa-Track-Launcher-Setup-1.2.18.exe` from the GitHub
   release page
2. Run it (Windows may warn "Unknown publisher" — click *More info* →
   *Run anyway*; the cert is the same self-signed one)
3. The NSIS installer detects the existing v1.2.13 install and
   upgrades in place, preserving `data/` (roster, catalog, offline
   reports, snapshots) and `.env` (`CF_INGEST_SECRET`, `GH_TOKEN`,
   `CF_WORKER_URL`, `LAN_IP`)
4. From v1.2.18 onwards, the cert baseline is fixed and future
   auto-updates work normally

## New admin endpoint

`POST /api/admin/close-stale-sessions`
- **Auth:** `X-Ingest-Secret` (same as the existing admin endpoints)
- **Body:** `{ sessions: [{emp_id, end_ms? }], dryRun?: boolean }`
  - `end_ms` optional; omitted → `min(started_at + 8h, now)`
  - `dryRun: true` returns the would_close summary without mutating
- **Response:** `{ ok, count, closed, skipped, results: [{emp_id, ok,
  process, abaya_id, abaya_code, started_at, end_ms, duration_sec,
  closed?, would_close?, error?}] }`
- **Side effects per session:** removes from `ACTIVE_SESSIONS`,
  appends to `COMPLETED_LOGS` (with `auto_closed: true`), pushes
  `session_finish` to the cloud, re-saves the offline-report snapshot
  and the SQLite snapshot

The endpoint is a sibling of `/api/reconcile-now` and
`/api/cloud-today/refresh` (same auth, same audit log).
