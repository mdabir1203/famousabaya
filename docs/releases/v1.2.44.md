# v1.2.44 — Pin END TIME contract: worker Finish tap is the source of truth

> **TL;DR:** The END TIME column on the per-employee day-report modal
> (and the `sessions.ended_at` field on the cloud D1) is now explicitly
> pinned to the exact Unix second at which the worker tapped Finish at
> the kiosk. Three enforcement layers ensure no future code path can
> recompute, clamp, or round this value: a runtime assertion in
> `cloudflare/src/handlers/ingest.js`, an explicit contract comment at
> the LAN push site (`server.js → req_finishWork`), and two unit tests
> in `tests/ceo-report.test.mjs` (`preserves ended_at byte-for-byte` +
> `never derives ended_at from duration_sec or started_at`). The
> contract is now documented in `AGENTS.md §2.1` and on the §10
> change-pre-check checklist.

---

## 1. The contract, in one sentence

`sessions.ended_at` (and the END TIME column on the dashboard) MUST be
the Unix second at which the worker tapped Finish at the kiosk. It is
NEVER to be derived from any formula — not from `started_at +
duration_sec`, not from a clamp, not from a round, not from a windowed
walk.

## 2. Why this matters

The `ended_at` field is what the operator audits. When they click on
Wahid on 2026-09-16 and see three identical-looking rows with end
times `11:04 AM / 7:03 PM / 9:54 PM`, they need to know whether
that's:

- (a) Three real Finish taps by the worker (real three abayas finished),
- (b) One Finish tap with two phantom duplicates from a buggy
  re-push (the v1.2.43 dup bug), or
- (c) A calculated/derived value the cloud dreamed up from the raw data.

In the operator's incident report from 2026-09-17, the answer was (b).
Pre-v1.2.43, the factory's `/api/admin/close-stale-sessions` endpoint
pushed a fresh `session_finish` with `ended_at = Date.now()` each
time it ran on the same orphan — creating three different "end times"
for one Start.

v1.2.43 added the LAN-side idempotency guard
(`isDuplicateSessionFinish`) so this can't happen again on the LAN
side. v1.2.44 makes the **invariant** explicit so a future agent
adding a new path (sync, batch import, REST endpoint, etc.) cannot
introduce a derived ended_at and silently break the operator's audit.

## 3. What was already correct (no behavior change)

I traced every layer of the ended_at path before making changes:

1. **LAN `req_finishWork`** (`server.js`):
   - `var now = Date.now();` captures the worker's Finish tap time.
   - `record.end = now;` stores it as ms in COMPLETED_LOGS.
   - `ended_at: Math.floor(record.end / 1000)` is pushed to the cloud as
     UTC seconds. **No recompute.**
2. **LAN `close-stale-sessions`**:
   - `endMs = min(now, started_at + 8h)` — capped at 8h for orphans.
   - `ended_at: Math.floor(endMs / 1000)` is pushed. The cap protects
     against multi-day orphans but never derives from anything other
     than `now` (the moment of close) and the start anchor.
3. **Cloud ingest** (`ingest.js`):
   - `INSERT OR IGNORE INTO sessions ... ended_at` with `p.ended_at` —
     verbatim. No clamp, no round, no shift.
4. **Cloud state.js**: `row.ended_at` is read and passed through
   `* 1000` (seconds → ms for the JSON payload, no semantic change).
5. **Cloud employee-day.js**: `ended_at: Number(r.ended_at) || 0` —
   verbatim, no transformation.
6. **Cloud ceo-pages.js → edFmtRange**: `new Date(Number(s.ended_at) *
   1000).toLocaleTimeString(...)` — pure formatting in the factory
   timezone. The underlying number is unchanged.

So **no current code path recomputes ended_at**. v1.2.44 makes that
explicit so future contributors don't accidentally introduce one.

## 4. What v1.2.44 adds

### 4.1 Runtime assertion in cloud ingest

`cloudflare/src/handlers/ingest.js` now rejects any `session_finish`
push that violates the contract:

```js
// v1.2.44 — END-TIME CONTRACT INVARIANT
const startedAtSec = Number(p.started_at);
const endedAtSec = Number(p.ended_at);
if (!Number.isFinite(startedAtSec) || startedAtSec <= 0) {
  return errRes('session_finish requires started_at > 0 (the worker tap time on Start)', 400);
}
if (!Number.isFinite(endedAtSec) || endedAtSec <= 0) {
  return errRes('session_finish requires ended_at > 0 (the worker tap time on Finish)', 400);
}
if (endedAtSec <= startedAtSec) {
  return errRes('session_finish ended_at must be strictly greater than started_at (got ended_at=' + endedAtSec + ', started_at=' + startedAtSec + ')', 400);
}
```

This is defense in depth. The LAN side already enforces the same
invariant (it builds `ended_at` from `Date.now()` which is always
positive and always > `started_at` since you can't finish before you
start). The cloud assertion catches any future code path that
forgets the invariant.

### 4.2 LAN-side comment block

`server.js → req_finishWork` now carries an explicit "do not derive
ended_at" comment block pointing at AGENTS.md §2.1:

```js
// v1.2.44 — END-TIME CONTRACT INVARIANT
// -------------------------------------------------------------------------
// `now` (assigned above) is the exact millisecond at which the worker
// tapped Finish at the kiosk. This value is preserved UNCHANGED as
// `record.end` here, then pushed to the cloud as `ended_at =
// Math.floor(record.end / 1000)`. The cloud stores it verbatim and
// the day-report modal renders it as-is. NEVER derive `end` /
// `ended_at` from any formula — see AGENTS.md §2.1 (timestamp
// contract) and the v1.2.43 release notes for the incident this
// guards against.
//
// `duration_seconds` below IS derived (it's the in-shift overlap of
// start..end), and that's correct — duration is a separate concept
// from the end timestamp. The DURATION column on the dashboard
// shows duration_seconds; the END TIME column shows ended_at.
// -------------------------------------------------------------------------
```

### 4.3 Unit tests in `tests/ceo-report.test.mjs`

Two new tests pin the contract:

**`handleEmployeeDay preserves ended_at byte-for-byte from the LAN push`**

Feeds the handler an `ended_at` of `1789542266` (= 11:04 AM Dubai) and
asserts the response carries `s.ended_at === 1789542266`. Any future
agent who adds a clamp, a recompute, a `Math.floor`, or a windowed
walk in the read path fails this assertion immediately.

**`handleEmployeeDay never derives ended_at from duration_sec or started_at`**

Feeds the handler `ended_at: 0` and asserts the response carries
`ended_at: 0` (or no row). This is the "do not synthesize from other
fields" guard — the historical bug pattern was that someone computed
`ended_at = started_at + duration_sec` to "fill in" missing data,
which silently corrupted the audit trail. The test fails if a
future code path does this.

### 4.4 Documentation in AGENTS.md

Two additions to `AGENTS.md`:

- **§2.1** (new subsection): The full END TIME contract with the

- **§10 checklist**: New entry "Did I touch `ended_at` in any path

## 7. Operator action items

**Nothing.** The runtime assertion is defense in depth — it cannot
reject a legitimate Finish tap (every real `session_finish` push has
`ended_at > started_at` and `ended_at > 0`). The unit tests run at
CI time and don't touch production. The AGENTS.md additions are
documentation.

## 8. Inbound bug surface: what the runtime assertion catches

The `ended_at <= started_at` check rejects:

- A future code path that pushes `ended_at = 0` as a "null marker"
  (the LAN never does this — `Math.floor(now/1000)` is always > 0).
- A bug where a `close-stale-sessions` orphan close somehow uses a
  past `endMs` (impossible given the current code, but if a future
  agent reorders the validation).
- A clock skew where the LAN's `Date.now()` somehow returns a
  number before `sess.started_at` (won't happen on a single machine,
  but defense for any future multi-source clock).

Any of these now produces a 400 response on the LAN's
`session_finish` push with a clear error message; the LAN's
`drainCeoIngestQueue` retries the push and the operator sees a
log line in `[CF] Push permanently rejected (recorded): 400 ...`.

## 9. What's NOT in v1.2.44 (deferred)

- **Clock-skew detection across LAN and cloud.** AGENTS.md's
  "factory server is source of truth" rule says we accept the
  LAN's clock as authoritative. If the factory server's clock
  drifts by more than a minute, the displayed END TIME drifts
  with it. A future release could ship an NTP check on boot and
  warn the operator if the LAN clock is off by >10s.
- **Sub-second tap resolution.** The current `Date.now()` gives
  millisecond precision on the LAN side, but the cloud stores
  seconds and the UI displays minute-precision ("8:55 PM"). If
  the operator wants to see "8:55:42 PM" in the future, the
  schema would need an `ended_at_ms` column alongside `ended_at`.
  Out of scope for this release — the contract is just that the
  displayed value matches the kiosk tap at the current resolution.
- **Audit-trail signing.** The current `ended_at` is trusted
  because the LAN is the source of truth. If the operator ever
  wants to prove to an external auditor that a Finish tap wasn't
  tampered with between the kiosk and the cloud, that's a
  separate cryptographic-signing feature. Out of scope.
