# AbaYa Track Launcher v1.2.13

A focused live-row fix. The dashboard's Live Active Sessions panel was
clamping every in-shift cell to 22h 0m 0s regardless of when the session
actually started (a 48h cap + 1-hour step in the cloud worker's in-window
overlap calculation), and the "this step (in shift)" cell the operator said
they no longer wanted to see was still on the screen.

This release ships the wall-clock build AGE cell that the v1.2.13 release
notes promised, drops the in-shift cell on both the cloud dashboard and the
offline factory dashboard, and adds a "last finished" cell so the operator
can see at a glance when this worker last tapped Finish on this abaya
instead of staring at a number that ticks every 2.5 seconds.

## Headline changes

- **Live "this build" cell** now shows wall-clock build age (e.g.
  "40h 30m 24s · started Aug 26, 2026"), not the in-window shift sum.
  The 24h-gap build rule and the contiguous-build walk are computed
  server-side from the sessions table; the cell renders
  `wall-clock NOW - build_start_unix` and ticks live on every render.
- **"this step (in shift)" cell removed** from the live row on both
  the cloud dashboard (`dashboard.farewellabaya.com`) and the offline
  factory dashboard (the LAN kiosk). The in-shift number still lives
  on the Daily / Weekly / Monthly / Yearly / Custom report modals and
  on the per-abaya totals panel for productivity calculations.
- **"last finished" cell** added to the live row: shows the most
  recent `ended_at` for this `emp_id` in the D1 `sessions` table (or
  `STATE.logs` on the offline dashboard), rendered in the factory's
  Asia/Dubai timezone. Replaces the live in-shift counter with a
  stable, non-ticking timestamp.
- **22h 0m 0s cap on the cloud worker removed** as a side effect of
  the live-row rewrite. The new cell reads from a per-abaya build
  map that doesn't depend on the old in-window overlap walk, so the
  stuck-at-22h bug that was masking every multi-day build is gone.

## Files changed in this release

- `cloudflare/src/handlers/state.js` — adds `abaya_builds` (per-build
  in-window totals, build_start_unix, last_session_unix, segments,
  wall_clock_span_sec) computed from the sessions table using a
  24h-gap build-boundary rule. Keeps `abaya_lifetime` for back-compat.
- `cloudflare/src/ui/ceo-pages.js` — drops the "this step (in shift)"
  and "total on item" cells. Adds "last finished" (from
  `STATE.logs` end-DESC) and "this build" wall-clock age (from
  `abayaBuildStartUnix(s.abaya_id)`).
- `public/dashboard.js` — mirrors the cloud UI on the offline factory
  dashboard. Adds `aggregateBuildsByAbaya` helper that walks
  `STATE.logs` and produces the same per-build map the worker sends.
- `tools/desktop-launcher/package.json` — bumped to 1.2.13.

## What factory PCs will see

- Factory PCs on the LAN mirror: auto-update over the next 2-4 hours
  brings the new offline dashboard with the live-row fix.
- The cloud dashboard at `dashboard.farewellabaya.com`: the Git
  integration picks up the new worker bundle on push to `main`, so
  the live row is fixed immediately (no factory action needed for
  anyone who watches the cloud dashboard from off-site).

## Operational notes

- No new D1 migrations in this release; the `abaya_builds` map is
  derived from the existing `sessions` table.
- The cloud worker and the offline factory dashboard can ship
  independently. If the cloud deploys first, the cloud dashboard
  shows the new cells while factory PCs still see the old
  in-shift / total-on-item pair — both are correct against their
  own data, just different shapes.
- If you notice a session where the "this build" cell shows "—",
  that means `abaya_builds` has no row for that `abaya_id` yet
  (only just-started, no finished sessions). It will populate as
  soon as the worker taps Finish on the first step of the build.
